# v1「夜の看板」設計メモ

- コンセプト: 商店街の大きな看板を、夜歩いて見上げたときの温度。深い紺〜藍（`--navy-0`〜`--navy-2`）の地に紙白（`--paper`）の文字、山吹（`--yamabuki`）は下線・チップ・数字だけの「一点」に絞った。ネオン管のようなグロー・ぼかし・パーティクルは一切使わず、すべて平面の色と1pxの罫線で作っている（看板の塗料であって、光る電飾ではない）。
- タイポグラフィ: ヒーローの見出しだけZen Kaku Gothic New 900の極太・極大（clamp(40px,9vw,120px)）にして「屋号の看板文字」の強さを出し、セクション見出し（つくった見本／料金／よくある質問など）はShippori Mincho 600で少し柔らかい版画的な質感に寄せた。ラベル・数字・kickerはIBM Plex Monoの小さめ広トラッキングに統一し、計器的な脇役に徹させている。
- 動き: 137.traident.jpから「1つの軸に演出を揃える」考え方だけを移植し、スクロール進捗をCSS変数`--bg-color`に橋渡しして紺の濃淡を3段階（`navy-0→navy-1→navy-2`）で線形補間、見出しは1文字ずつrise-up、ギャラリー/料金/3ステップはIntersectionObserverでスタッガー出現、ヘッダーの実績数字はeaseOutCubicでカウントアップ。WebGL・カーソル追従・音は導入していない（オーバースペック＆世界観不一致のため不採用、詳細はref-analysis.md参照）。
- 申込フォーム: 「名前を入れる→業種を選ぶ→紹介文を書く→（連絡先・くわしく入れる・送信）」の4段を`opacity`+`max-height`で開閉し、`display:none`/`visibility:hidden`を使わない設計にした。理由は、隠れている間もrequired項目（説明文など）がフォーカス可能なまま残るようにするため（ブラウザのネイティブバリデーションが「フォーカスできない要素」としてエラーを出すのを避ける、意図的な簡略化）。任意項目（予約URL・Instagram・LINE・メニュー・写真・キャッチコピー・色・営業時間）は元からある`<details>`にすべて集約し、業種・色の雰囲気のradioはデフォルト値のvalidityに頼りつつ見た目だけチップ化した。
- assets/app.js は無改変でそのまま読み込み、LIVE PREVIEW（`#sample-site`）の構造・class名も元サイトを踏襲して再スキンした（挙動を壊すリスクを最小化するため）。`google-client-id`はこのローカル検証用ドラフトでは意図的に空にしてある（本番クライアントIDはfreehp.jpオリジン限定で許可されており、ローカルで読み込むとGSI_LOGGERの403が出るため）。本番ドメインに統合する際は元の値に戻すこと。
